# SlimLLM 简历项目描述

适用方向：大模型应用开发 / Python 后端 / 推理服务工程。以下数字均对应本机真实实验，数据为合成工单。

## 简历正文（可选三至四条）

**SlimLLM｜单卡大模型微调与结构化推理服务**

技术栈：Python、PyTorch、Transformers、PEFT/TRL、bitsandbytes、FastAPI、Pydantic、Redis、vLLM、asyncio/httpx、Vue3/Vite。

- 构建电商售后七字段 JSON 抽取流程，生成并校验 499 条合成工单，按近似模板分组冻结 399/50/50 划分，区分格式合法率、字段准确率与整条匹配率，保存预测及实验来源哈希。
- 在 RTX 4060 8GB 上完成 Qwen3-1.7B 的 NF4 QLoRA 微调，采用 LoRA r=8、答案专用损失与梯度检查点；固定 50 条测试集字段宏准确率由 63.71% 提升至 85.14%（+21.43 个百分点），最终 Adapter 约 6.16 MiB。
- 使用 FastAPI 实现抽取与健康检查，结合 Pydantic/原文校验、有界 FIFO、等待超时及可选 Redis 精确缓存；在固定并发 8 测试中，请求成功率由原忙时拒绝策略的 12.5% 提高至 100%，不将排队改善描述为 GPU 吞吐量提升。
- 接入 WSL2 单引擎 vLLM 并保留 Transformers 回退；同一 32 条工单、关闭缓存的并发 8 测试中，成功 RPS 约从 0.367 提高至 0.747，P95 从 21.219 秒降至 10.973 秒；两后端对应输出一致。
- 接入完整 JSON Schema 约束解码并区分结构/语义指标：独立 12 条回归枚举与 Schema 合法数由 11/12 提升为 12/12，保留优先级等错误证据；提供 Vue3 演示页，覆盖输入、JSON 展示、健康检查与错误提示。

## 字数较少时

基于 Qwen3-1.7B 构建售后工单结构化抽取服务，完成合成数据治理、8GB 单卡 QLoRA 与 FastAPI/有界队列/Redis 工程化；固定 50 条测试字段宏准确率提升 21.43 个百分点。接入 WSL2 vLLM，在固定并发 8、每档 32 次请求的实验中达到 100% 成功率、0.747 RPS，P95 为 10.973 秒，保留 Transformers 回退。

## 面试时必须附带的口径

- 不是客户项目或线上业务数据，没有独立人工金标，不声称生产效果。
- 微调效果来自 50 条测试；服务压测只用其中固定 32 条，不能混用 85.14% 与 86.61%。
- 入口并发 8、GPU max_num_seqs=2，其余请求排队；不能表述为“支持任意高并发”或“8 路 GPU 并行”。
- vLLM 的约 2.03 倍 RPS 来自非交错历史参考；并发 1 P95 变差，整卡显存采样峰值增至约 7.01 GiB，未验证生产 SLA。
- 训练阶段 3.10 GiB 是 PyTorch 已分配峰值，不是加载峰值或整卡峰值；训练/验证循环耗时约 1018 秒，不包含全流程所有步骤。
- 当前保留 97 项 Python 和 10 项前端契约/控制流测试及独立真实实验记录；测试 fixture 不代表模型推理。上述吞吐数据来自未开启约束解码的历史配置；本轮未测约束模式性能。
